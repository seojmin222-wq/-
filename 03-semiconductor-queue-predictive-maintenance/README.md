# 큐타임 위반 예방 자동 라우팅 & O-ring 열화 예지보전 시스템 – PLC·SCADA·DB·분석 4-Layer 통합

> 🚧 진행 상태: 마무리 단계 (PLC 최종 동작 검증 중)

## 개요
반도체 공정에서 웨이퍼 큐타임(Q-Time) 초과 시 로트 폐기, 챔버 O-ring 열화 미감지로 인한 웨이퍼 불량이 발생하지만 이를 자동 감지·대응하는 통합 시스템이 부재했습니다. 이를 해결하기 위해 제가 먼저 PLC 로직 순서도와 큐타임 위반 예방 자동 라우팅 아이디어를 제안했고, 이를 바탕으로 4인 팀 프로젝트로 하드웨어부터 PLC·SCADA·DB·데이터분석까지 아우르는 4-Layer 파이프라인 구축을 목표로 진행했습니다.

- **기간**: [2026.08 ~ 진행중]
- **참여 형태**: 팀 프로젝트 (4인, 팀장)
- **담당 역할**: 팀장 — 큐타임 위반 예방 자동 라우팅 아이디어 및 PLC 로직 순서도 최초 제안, 세부 구현 방안 설계 및 팀원 역할 배분, 전체 일정관리, MPS 하드웨어 재구성, PLC/서보 배선, iFIX 설비 개요도 작화, 3D 프린팅 부품 설계 총괄 및 팀원 PLC 로직·iFIX 구현 조율

## 배경 및 문제 정의
반도체 공정에서 웨이퍼 큐타임 초과 시 로트가 폐기되고, 챔버 O-ring 열화를 미리 감지하지 못해 웨이퍼 불량으로 이어지는 문제가 있었습니다. 이를 자동으로 감지·대응할 수 있는 통합 시스템이 없어, 현장제어부터 데이터 분석까지 아우르는 4-Layer 파이프라인을 직접 구축하기로 했습니다. 프로젝트 착수와 동시에 이 문제를 해결할 방법으로 어떤 시퀀스로 데이터를 판정하고 어떤 값을 릴레이로 넘겨 큐타임 위반을 예방하는 자동 라우팅을 구현할지에 대한 아이디어를 제가 직접 제안했고, 이 구상을 구체적인 작업 단위로 정리해 팀원들에게 역할을 배분했습니다.

## 사용 기술 / 툴
- PLC/서보: MELSEC PLC, MR-J5 서보모터
- HMI: GOT HMI
- SCADA: iFIX (OPC-UA 연동)
- DB: SQLite
- 데이터 분석: Python (pandas), LSTM 시계열 분석
- 하드웨어: MPS 설비 재조립, 3D 프린팅 부품 설계·제작
- 협업/일정관리: 주 단위 팀 공유 문서 트래킹

## 시스템 구성 (4-Layer 아키텍처)
![시스템 아키텍처](images/03-architecture.png)

| Layer | 구성 요소 | 역할 |
|---|---|---|
| 1. 현장제어 | MELSEC PLC, MR-J5 서보, GOT HMI | 로트·압력·큐타임 데이터 수집, 위험등급·열화 판정, 위험 로트 우선 이송, 현장 경보 표시 |
| 2. SCADA | iFIX (OPC-UA) | 큐타임 히트맵, O-ring 상태 게이지, KPI 대시보드 실시간 시각화 |
| 3. DB | SQLite | 로트별·시간대별·챔버별 이력 자동 적재 |
| 4. 분석 | Python(pandas), LSTM | 병목 구간 분석, 압력 강하율 기반 열화 패턴 도출, 최적 보전 주기 산출 |

## 주요 구현 내용

### 1) PLC 로직 순서도 설계 및 초기 아이디어 제안 (팀장 역할)
프로젝트 시작과 동시에 큐타임 위반을 예방하는 자동 라우팅 아이디어를 팀원들에게 먼저 제안했습니다. 로트·압력·큐타임 데이터를 어떤 순서로 판정하고 어떤 데이터를 릴레이로 넘겨 위험 로트를 우선 이송할지에 대한 PLC 로직 순서도를 직접 설계해 제시했습니다. 제가 제안한 아이디어였기 때문에 전체 구현에 필요한 세부 작업(현장제어 로직, SCADA 시각화, DB 적재, 데이터 분석 등)을 스스로 정리하고, 각 팀원이 맡을 역할과 작업 범위를 자세한 설명과 함께 배분해 프로젝트 초기 방향을 이끌었습니다.

### 2) 프로젝트 일정관리 (팀장 역할)
주 단위로 지난주 완료 업무와 이번주 목표를 팀 공유 문서로 트래킹했습니다. PLC 로직 구현(팀원 담당)과 하드웨어 재구성·iFIX 설비 개요도 작화(본인 담당) 등 역할을 분담하고 진행 상황을 조율했습니다.

### 3) 4-Layer 시스템 아키텍처 설계
MELSEC PLC가 로트·압력·큐타임 데이터를 수집해 위험등급·열화를 판정하고, MR-J5 서보 기반 컨베이어가 위험 로트를 우선 이송하며, GOT HMI가 현장 경보를 표시하도록 설계했습니다. OPC-UA로 iFIX SCADA에 큐타임 히트맵·O-ring 상태 게이지·KPI 대시보드를 실시간 시각화하고, SQLite DB에 로트별·시간대별·챔버별 이력을 자동 적재했습니다. 이후 Python(pandas)으로 병목 구간을 분석하고, 압력 강하율 기반 LSTM 시계열 분석으로 열화 패턴을 도출해 최적 보전 주기를 산출하는 4-Layer 파이프라인을 설계했습니다.

### 4) MPS 하드웨어 재조립 및 부품 재설계
챔버 설치를 위해 분배·공급 실린더 위치를 조정하고 재조립했으며, 미사용 센서 배선을 정리하고 고장난 솔레노이드를 진단했습니다. 카메라-PLC 연동 오류(바코드 인식 불량)의 원인을 파악해 수정했습니다. 실린더 위치 조정으로 발생한 간섭 문제는 구조 변경으로 해결했고, 길이가 맞지 않게 된 분배막대는 3D 프린팅으로 재설계·재제작했습니다.
![하드웨어 재조립](images/03-hardware.png)

### 5) iFIX 작화(설비 전체 개요도) 설계
SCADA 화면에 큐타임 히트맵·O-ring 상태 게이지 등을 얹기 위한 바탕 화면으로, MPS 설비의 실린더·서보 결합부와 컨베이어·비전 게이트 배치를 그대로 반영한 설비 전체 개요도를 iFIX 작화 기능으로 직접 그렸습니다. 좌우 MPS 스테이션의 실린더·서보 결합부를 확대해 보여주는 상세 시점 화면과, 컨베이어·게이트까지 포함한 설비 전체 구성을 한눈에 보여주는 개요 시점 화면, 두 가지 시점으로 나눠 작화해 현장 상태를 직관적으로 파악할 수 있도록 구성했습니다.
![iFIX 작화 - 상세 시점](images/03-ifix-detail.png)
![iFIX 작화 - 전체 개요 시점](images/03-ifix-overview.png)

### 6) PLC·서보 트러블슈팅
PLC 2대(각 MPS 담당)를 포트·IP 주소로 구분해 PC 1대에서 동시 제어했습니다. 서보 알람 발생 시 배선 미결선을 확인해 수정했고, 리미트센서 신호 불량으로 인한 서보 정지는 센서 교체로 해결했습니다. I/O 센서판에서 센서 간 오동작 간섭을 발견해 미사용 센서를 제거함으로써 문제를 해소했습니다.

### 7) 3D 프린팅 반복설계
한 번에 출력이 불가능한 부품을 조립식 구조로 재설계해 분할 출력·조립했습니다. 챔버-오링 접합부 구조를 개선해 조립성을 확보했고, 웨이퍼 진입 오차는 공급 위치·속도 조정으로 해결했습니다.
![3D 프린팅 부품](images/03-3dprint-parts.png)

### 8) 컨베이어 연동
PLC-컨베이어 구동용 24V→12V 컨버터 배선·전압 세팅 절차를 직접 수립하고, 래더 로직으로 컨베이어 시작/정지 제어를 구현했습니다.

## 결과 및 성과
- 큐타임 위반 예방 자동 라우팅 아이디어 및 PLC 로직 순서도를 최초 제안하고, 이를 토대로 팀원 역할 배분을 주도
- 4-Layer(현장제어-SCADA-DB-분석) 파이프라인 설계 및 하드웨어 재구성 완료
- iFIX 설비 개요도를 상세/전체 두 시점으로 직접 작화해 SCADA 시각화 기반 화면 구성
- 서보·센서·PLC 통신 관련 트러블슈팅 4건 이상 원인 진단 및 해결
- 3D 프린팅 부품 재설계·재출력을 3회 이상 반복해 조립 완성도 확보
- 현재 PLC 최종 동작 검증과 3D 프린팅 마무리 단계로, 프로젝트 완주를 앞두고 있음 (진행중)

## 회고 / 배운 점
아이디어 구상 단계부터 직접 시퀀스와 데이터 흐름을 설계해 팀원들에게 제안하고 역할을 배분해본 경험을 통해, 단순히 맡은 파트를 구현하는 것을 넘어 프로젝트 전체 방향을 설계하고 이를 남에게 설득력 있게 전달하는 역량을 키울 수 있었습니다. 하드웨어(챔버·실린더 설계) - 제어(PLC/서보) - 모니터링(iFIX SCADA) - 데이터 분석(Python/LSTM)을 아우르는 4-Layer 시스템을 팀장으로 리드하며 스마트팩토리 전체 파이프라인 설계 역량을 확보했습니다. 매뉴얼대로 되지 않는 하드웨어 문제(센서 간섭, 배선 누락, 출력 실패)를 원인 단위로 쪼개 진단하고 반복 설계로 해결하는 문제해결력을 체득했습니다. 또한 주간 단위 일정관리로 팀원 간 작업 의존성을 조율하는 리더십 경험도 쌓을 수 있었습니다.
