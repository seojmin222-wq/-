# Raspberry Pi5·YOLOv8 기반 실시간 차량 번호판 인식 주차관리 시스템

## 개요
딥러닝 수업 최종 프로젝트로, GPU 서버 없이 Raspberry Pi5(CPU-only) 같은 저사양 임베디드 환경에서도 실시간으로 동작하는 차량 출입 자동화 시스템을 구현한 프로젝트입니다. YOLOv8 객체 탐지 모델과 EasyOCR을 함께 구동해 카메라 영상에서 번호판을 찾고 문자를 인식한 뒤, 결과를 CSV로 자동 기록하는 실시간 파이프라인을 만드는 것이 목표였습니다.

- **기간**: [2026.05 ~ 2026.06]
- **참여 형태**: 개인 프로젝트
- **담당 역할**: 기획·모델 학습·최적화·배포 전 과정 단독 수행

## 배경 및 문제 정의
딥러닝 수업 최종 프로젝트로, GPU 서버가 아닌 저사양 엣지 디바이스에서도 실시간으로 동작하는 차량 출입 자동화 시스템이 필요했습니다. 프로젝트 진행 전 Hough Transform 기반 차선 검출을 먼저 학습하고 이를 CNN 기반 접근으로 확장하며 영상처리·딥러닝 파이프라인에 대한 기초를 다진 뒤, Raspberry Pi5 위에서 YOLOv8과 EasyOCR을 결합한 실시간 번호판 인식 파이프라인 구축에 들어갔습니다.

## 사용 기술 / 툴
- 언어/환경: Python, Linux CLI, venv 가상환경
- 객체 탐지: YOLOv8 (yolov8n.pt 전이학습, Ultralytics)
- 문자 인식: EasyOCR (ko/en)
- 영상처리: OpenCV (그레이스케일 변환, CLAHE, ROI crop), Hough Transform, CNN 기반 차선 검출
- 하드웨어: Raspberry Pi5 (CPU-only)
- 원격 개발: MobaXTerm (SSH)
- 데이터 저장: CSV (parking_log.csv)
- 메모리 관리: gc.collect(), torch 캐시 정리

## 시스템 구성

**추론 파이프라인**: 카메라 영상 → 중앙 300×300 ROI crop → YOLOv8 번호판 탐지 → 전처리(리사이즈/그레이스케일/CLAHE) → EasyOCR 인식(allowlist 적용) → 정규식 후처리 → parking_log.csv 저장

## 주요 구현 내용

### 1) YOLOv8 경량화 및 ROI 기반 추론 최적화
YOLOv8(yolov8n.pt 사전학습 모델)을 커스텀 번호판 데이터셋으로 전이학습했습니다. RPi5의 연산 한계를 고려해 epochs=10, imgsz=320, batch=2(기본값 16에서 축소), device='cpu', workers=1로 하이퍼파라미터를 저사양 환경에 맞게 조정했습니다. 또한 전체 프레임이 아닌 화면 중앙 300×300 정사각형 ROI만 잘라 YOLO 추론에 넣는 구조로 설계해 CPU 연산량을 줄이고 프레임 처리 속도를 확보했습니다.

![CNN](프젝2이미지/RP1.png)
### 2) EasyOCR 인식 정확도 개선
EasyOCR(ko/en) 인식 전에 이미지 리사이즈(폭 240px 미만 시 확대), 그레이스케일 변환과 CLAHE(대비 보정) 전처리를 적용했습니다. OCR 시에는 한글 자모·숫자로 구성된 allowlist를 지정해 오인식 문자를 원천 차단하고, 이후 정규식으로 후처리해 최종 텍스트를 정제했습니다.

![탐지·인식 결과 화면](프젝2이미지/RP4.png)

### 3) 저사양 디바이스 안정성 확보
반복적으로 다운되는 문제가 발생해, READ_INTERVAL(3초) 기반 쿨타임과 "System Cooling..." 카운트다운 UI로 과도한 연속 추론을 방지했습니다. 인식 결과는 별도 parking_log.csv에 즉시 append 저장해 크래시 발생 시에도 데이터 유실을 최소화했고, gc.collect() 및 torch 캐시 정리를 루프마다 호출해 메모리 누적을 방지했습니다.

번호판은 탐지되지만 최종 결과가 출력되지 않는 문제는, YOLO 신뢰도 임계값(CONF_TH=0.50)과 OCR 완독 판정 조건(문자열 길이 7~8자 검증)을 함께 튜닝해 해결했습니다.

### 4) 개발·배포 환경
MobaXTerm으로 Raspberry Pi5에 SSH 원격 접속, venv 가상환경 위에서 Linux CLI 기반으로 개발·테스트·배포까지 전 과정을 단독으로 수행했습니다.

## 결과 및 성과
- 실제 구동 로그 기준 약 154분간 CPU 사용률 41%, 메모리 2.82/3.95GB 수준 유지
- 동일 차량 번호판("123가 4568")을 54~61%대 정확도로 약 10초 간격으로 반복·안정 인식
- 디바이스 다운 없이 장시간 연속 동작을 확인하고 최종 발표 완료
- 저사양 엣지 디바이스에서 실시간 비전 추론 파이프라인을 기획부터 배포까지 단독으로 구축

## 회고 / 배운 점
리소스가 제한된 엣지 컴퓨팅 환경에서 모델 크기·입력 해상도·배치 크기 등 하이퍼파라미터를 하드웨어 제약에 맞춰 트레이드오프하는 경험을 쌓았습니다.

특히 번호판이 탐지는 되지만 최종 결과가 출력되지 않는 문제를 해결하는 과정에서, YOLO의 탐지 신뢰도(CONF_TH)와 OCR의 문자열 길이 검증이라는 서로 다른 단계의 임계값이 함께 맞물려야 최종 결과가 정상적으로 출력된다는 것을 확인했습니다. 이를 통해 파이프라인의 한 단계만 보고 문제를 판단하기보다, 탐지-인식-후처리 전 단계를 함께 놓고 원인을 추적하는 디버깅 습관을 갖게 됐습니다. 예상치 못한 하드웨어 제약(반복 다운, 미출력)의 원인을 로그·리소스 모니터링으로 직접 분석하고 해결하며 실전형 디버깅·최적화 역량도 함께 확보했습니다.
